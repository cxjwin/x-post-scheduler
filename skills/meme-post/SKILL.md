# meme-post：热梗雷达 → 原创二创 → 短推

## 红线（本 skill 存在的前提，先读）

- **不搬运**：段子的价值就是表达本身，照抄或微改别人的句子是洗稿。只提取「梗格式 / 话题 / 情绪点 / 笑点机制」，最终表达必须全新。
- **不碰原图**：不去水印，也不以原图为底做编辑生成（衍生作品仍是侵权）。原帖有图时，把图的**创意概念**用文字描述出来，让 Codex 从零生成——只保留笑点机制，构图、角色、细节全部是新的。
- **相似度自检**：文案写完与原帖逐句对比，句式或用词雷同过半就推翻重写。
- 拿不准算不算「梗格式」还是「具体表达」时，宁可重写。

## 第 1 步：找梗

两种入口：

- **用户丢链接** → 抓取该帖。微博 / 即刻 / 小红书大概率反爬，直接走 chrome-devtools 浏览器路线（`new_page` + `take_snapshot`，只操作自建标签页，参考 x-post-scheduler 第 1 步）。
- **用户说「看看有什么梗」** → 扫雷达源，挑 2~3 个适合人设发挥的：微博热搜（s.weibo.com/top/summary）、知乎热榜、V2EX 热议、Hacker News。只记话题和梗格式，不保存原文。

## 第 2 步：提取梗点

从原帖中提炼（用自己的话记录，不引用原句）：

- 话题 / 情绪点（大家在笑什么、气什么）
- 梗格式（例：「以为是青铜，结果是王者」句式、对比图结构、反转结尾）
- 若有图：图的创意概念（例：「用考试成绩单的形式列日常行为」），**不描述原图的具体画面细节**

## 第 3 步：原创二创

- 人设与 x-post-scheduler 一致（默认一线程序员 / AI 从业者，自嘲、反差、行业内梗，不装腔；按账号主人自行改写）
- **必须加入原梗没有的东西**：新的信息点、行业视角或额外反转——这是「二创」和「换皮」的分界线
- **短！** 段子推文一两行最佳，超过三行笑点就散了。不用要点列表、不用长推结构（与 x-post-scheduler 完全不同）
- **排版**：铺垫句和梗点句之间**空一行**——留白就是节奏，读者在空行处换气，笑点落得更准
- 产出 **2~3 条候选**供用户挑（幽默主观性强，多给选择比赌一条准要好）

## 第 4 步：配图规则

- **原帖有图** → 提取梗点概念后，写全新的画面描述让 Codex 生成原创二创图（`<输出目录>` 为配置的 output_dir，默认 `./output`）：

```bash
codex exec --skip-git-repo-check -C <输出目录> --sandbox workspace-write \
  '$imagegen 生成一张 1536x1024 横版幽默风格图片：<全新的画面描述，只保留笑点机制>。风格可以比新闻海报更放飞（漫画感/表情包感都行），但不要模仿任何已存在的具体形象。图中文字（如有）必须为简体中文且准确无误。保存为 <日期-slug>-meme.png'
```

  生成后 Read 目检（文字、构图、有没有意外撞脸知名形象），有问题重生成。
- **原帖无图** → 不配图，纯文字发。不要为了配图而配图。

## 第 5 步：人工确认（必须，本 skill 不适用自动发布授权）

段子的翻车率远高于新闻（幽默主观、语境敏感），展示 2~3 条候选文案（+ 二创图）等用户明确挑选后才碰 Buffer。x-post-scheduler 的自动发布授权（即使已开启）**不覆盖**本 skill。

## 第 6 步：发布

- 与 x-post-scheduler 共用全部基础设施：Buffer 频道与图床走同一份配置（见 x-post-scheduler 的 SKILL.md 第 0 步与仓库 README），push + raw URL 流程和全部已验证 API 事实也一致——详见其「已验证的 Buffer API 事实」小节。没有 Buffer MCP 时同样可用 `buffer-post.mjs` 脚本发布。
- 段子默认**不需要首评链接**；如果是对特定热帖的二创且用户想给原作者引流，可在首评放「灵感来自：{URL}」（问一下用户）
- 发布后报告：推文全文（+图）、发布链接、提醒可回「删掉」撤下
